# Voicescape UX Audit — Claims vs Reality

**Date:** 2026-09-12 · **Repo:** `~/workspace/voicescape/frontend` (Next.js 14)
**Method:** Three parallel code-level audits (landing claims, core money flows, town hall/social/mobile). Audit only — no code changed.
**Founder's lens:** Brandon works from an Android phone; mobile UX weighted heavily throughout.

---

## Executive summary

The good news: **the dapp is overwhelmingly honest.** No mocked data, no "coming soon" buttons, no placeholder UI, no fake wallet fallbacks, no dead `href="#"` links. The headline promises — blockpages, on-chain identity, atomic 98/2 tips, no-escrow marketplace, HCS town hall, real Hedera mainnet — are all real and verified in code.

The bad news: **the failures are all in the same defect classes Brandon has already flagged in the past** — developer jargon shown to end users, success claimed on wallet response alone, silent failures after the user paid a chain fee, and fee/cost claims that don't match what the user actually pays. There are **2 P0s** (both can brick a core flow entirely), **~14 P1s**, and a long tail of P2 polish.

## P0 — Blocks core use (fix before anything else)

### P0-1. Tips are completely dead if `NEXT_PUBLIC_TIPS_ADDRESS` is unset — and the hardcoded mainnet constants are a decoy
- **Files:** `lib/contracts.ts:70` (`normalizeContractAddress`), `lib/contracts.ts:114`
- **What happens:** `getTipsAddress()` returns `undefined` when the env var is missing. `MAINNET_TIPS_ID` / `MAINNET_TIPS_EVM` (0.0.10854060) exist in the file but are only mapping keys, never fallbacks. Every tip dies with: *"NEXT_PUBLIC_TIPS_ADDRESS is not set (or is a placeholder/unknown format) — deploy the contracts and add the real Tips EVM address to your env."*
- **Why P0:** One missing env var bricks 100% of tipping, the app's core money flow, and the error is deployer jargon shown to a phone user who tapped "Tip $5".
- **Fix:** Use the mainnet constants as real fallbacks (the app is mainnet-first everywhere else — `/api/resolve` already hardcodes mainnet), and render a human error at the UI boundary.

### P0-2. Pinata down/misconfigured = publish fully blocked, with jargon errors and no fallback
- **Files:** `app/api/pin/route.ts:285`, `lib/server/publish.js:17`
- **What happens:** Missing `PINATA_JWT` → 500 *"Cannot publish: PINATA_JWT is not set. Create a key at https://app.pinata.cloud and set the environment variable."* — shown verbatim to the user. There is **no fallback pin path** (web3.storage/Storacha was deliberately dropped). A Pinata outage, exhausted free quota, or bad JWT turns the entire builder into a dead end.
- **Why P0:** Publishing is the other core flow (no page = no tips = no badges = no builders room). This is exactly the "Needs Attention" incident Brandon hit today.
- **Fix:** Keep the block, but the copy must read as user guidance ("Publishing is temporarily unavailable — your draft is saved, try again later"), with the config details logged server-side only.

## P1 — Confusing, misleading, or likely support tickets

### P1-1. Marketplace claims "Purchase complete ✅" on wallet submission alone — no on-chain verification
- **File:** `app/(townhall)/marketplace/ListingDetailClient.tsx:200`
- **What happens:** `startBuy` sets `buy.kind = "done"` right after `buyListing()` resolves. The HashPack receipt only confirms *submission*, not on-chain success.
- **Why it matters:** This is **the exact defect class Brandon already flagged** ("never claim on wallet response alone") — the tip flow was fixed to verify via the mirror node first, but the marketplace flow was not. A failed-but-submitted tx tells the buyer "Purchase complete ✅".
- **Fix:** Mirror the tip pattern — verify on-chain before "confirmed", or downgrade the copy to "Payment sent — confirming…" until the mirror node confirms.

### P1-2. Tip verification can report a successful tip as failed (MetaMask users)
- **File:** `app/[username]/page.tsx:133` (`verifyTipOnChain`)
- **What happens:** Verification hardcodes the mainnet mirror node contract-result endpoint and assumes an SDK-format txId. The **EVM/MetaMask path** returns an EVM tx hash (`receipt.hash`, `lib/tx.ts:160`), which will never match. After ~30s of polling the user sees *"Tip failed: Transaction submitted but on-chain verification failed"* — **money moved, user told it failed**. Mirror-node lag beyond ~30s produces the same false negative for anyone.
- **Fix:** Handle EVM tx hashes (or skip verification for the EVM sender with an honest "submitted — check explorer" state).

### P1-3. Builders badge: 1-hour KV cache with no production invalidation locks newly-qualified users out
- **Files:** `lib/server/badges.ts:28` (60-min cache), `badges.ts:93` (`clearBuilderBadgeCache` labeled "test helper", nothing calls it in production)
- **What happens:** A user who just received their first tip sees the 🔒 locked screen and gets 403s for up to an hour. There is no "last checked" timestamp or manual recheck button. Mirror-node/KV outages also resolve to *locked* with no "couldn't verify" state — a working builder is told they haven't earned it.
- **Fix:** Invalidate on tip receipt (or shorten TTL + add a recheck button + a "couldn't verify" state distinct from "not earned").

### P1-4. Forum board and CommentWall: verify failure → `console.error` only, after the user paid an HCS fee
- **Files:** `app/(townhall)/forum/BoardClient.tsx:173-179` (comment literally says "Show the error", code only `console.error`), `components/townhall/CommentWall.tsx:60-80`
- **What happens:** The user signed and paid for an HCS tx. On server-verify failure the UI shows **nothing**. CommentWall is worse: it has no stream and no refetch, so the paid comment silently never appears.
- **Fix:** Visible error + retry, and a refetch/stream for CommentWall.

### P1-5. Badge holders see a permanent fake "◌ reconnecting — polling every 5s" in #builders
- **Files:** `components/townhall/useStream.ts:88`, `app/(townhall)/chat/[room]/ChatRoomClient.tsx:224`
- **What happens:** `EventSource` cannot send the `x-vs-session` header (session travels in headers only, no cookie — `lib/server/townhall/route-auth.ts`), so the SSE handshake 403s, falls back to 5s polling which works fine — but the status line reads "reconnecting" **forever**, even though messages flow.
- **Fix:** Pass session via query param for EventSource, or show "● live (polling)".

### P1-6. Trending "Most tipped pages this week" is not this week
- **Files:** `components/TrendingFeed.tsx:55`, `app/api/trending/route.ts:18-25`
- **What happens:** The query fetches `…/results/logs?order=desc&limit=100` with **no timestamp filter** — it's the last 100 tip events *ever*. The route's own comment claims "last 7 days" but the code doesn't implement it.
- **Fix:** Add `timestamp=gte:` filtering, or change the copy to "Most tipped pages".

### P1-7. A second, unexplained wallet prompt fires right after "Published!"
- **File:** `app/builder/page.tsx:1686-1719`
- **What happens:** The referral HCS submit runs *after* `setStatus("ok", "Published!")` with **zero status text**. The user sees "Published!" while HashPack pops a second signature request (a dust-fee HCS write). Dismissing it silently skips the referral. On a phone, two back-to-back signature prompts reads as suspicious.
- **Fix:** Its own status line ("Recording your referral — one more signature…") or defer post-redirect.

### P1-8. "Create your free page" hides real costs (HBAR gas + AI edits)
- **Files:** `lib/i18n/dictionaries.ts:118` (`"landing.openBuilder": "Create your free page"`), `app/builder/page.tsx:1068-1072`
- **What happens:** Platform charges nothing, but publishing needs HBAR for gas, and every AI edit costs money (BYOK Anthropic key, or x402 per-edit wallet payment, default $0.25/request). The landing discloses neither. A phone-first visitor discovers two paywalls the landing never mentions.
- **Fix:** One line under the CTAs: "Free to create — you'll need a little HBAR for network fees." Disclose AI-edit pricing at step 2.

### P1-9. "Fees around $0.0001" understates the actual tip cost (~200×)
- **File:** `lib/i18n/dictionaries.ts:131`, `dictionaries.ts:51`
- **What happens:** $0.0001 is accurate for HCS submits/transfers, but a **tip is a smart-contract call** (`VoicescapeTips.sol:94`). The project's own mainnet tip test burned **~$0.02 of gas** — ~200× the advertised figure.
- **Fix:** Scope the claim ("transfers from $0.0001; contract tips cost a few cents").

### P1-10. Referral credit silently drops for EVM/MetaMask users and on HCS dismissal
- **Files:** `app/builder/page.tsx:1718` (try/catch swallows), `lib/tx.ts`
- **What happens:** `hcs.submit()` needs a Hedera pairing; MetaMask users get an internal "Connect a Hedera wallet" message that the builder's catch swallows. **An EVM user's referrer never gets credit, with no message to anyone.** Same when the user dismisses the second wallet prompt (P1-7).
- **Fix:** Surface a note when referral recording is skipped, or restrict referral claims to Hedera-wallet flows.

### P1-11. `/api/resolve` hardcodes the registry address + mainnet RPC, ignoring the env var
- **File:** `app/api/resolve/route.ts:18-19`
- **What happens:** Pins `REGISTRY_EVM = 0xd87F8113C5bcc47c40dC26a43fFa9B1629385a58` and `mainnet.hashio.io`, while publish reads `NEXT_PUBLIC_REGISTRY_ADDRESS`. If the registry ever rotates, the existence check and the 30s confirm loop query the **wrong contract** — a taken name misread as free (→ on-chain revert), or a successful register that "times out" in the confirm loop.
- **Fix:** Use the env var, or add a boot-time assertion that the two agree.

### P1-12. Internal config jargon shown verbatim to end users (4 instances)
- `NEXT_PUBLIC_TIPS_ADDRESS is not set…` (tip flow), `NEXT_PUBLIC_REGISTRY_ADDRESS is not set…` (publish), `PINATA_JWT is not set. Create a key at https://app.pinata.cloud…` (publish), `NEXT_PUBLIC_WALLETCONNECT_PROJECT_ID is not set…` (connect)
- These are *deploy-config* errors, not user errors. UI should say "temporarily unavailable — try again later"; details go in server logs.

### P1-13. HashPack in-app auto-connect has no cancel
- **File:** `components/WalletConnect.tsx:223`
- **What happens:** Inside HashPack's in-app browser, a *disabled* "Connecting…" button renders during `autoConnectPending`. If pairing drags (up to the 180s timeout), the user stares at a dead button with no retry or cancel — on a phone this reads as a frozen app.
- **Fix:** Cancel/retry affordance during auto-connect.

### P1-14. DM 10s poll wipes the open report form and error banners every tick
- **File:** `app/messages/page.tsx:62-77`
- **What happens:** `loadThread` calls `setShowReport(false)` + `setSendError(null)`; the interval fires every 10s, so an open report form closes under the user's fingers and error banners vanish on their own.
- **Fix:** The poll should refresh messages only, never reset form state.

## P2 — Polish, copy, and mobile nits

### Claims & copy
- **"Get listed. Get hired. Get paid."** — hiring happens off-page by design (no pay button; buyers copy the endpoint and use an external x402 client — `app/agents/hire/HireAgentsClient.tsx:31-32`). Honest in-panel copy mitigates, but non-technical humans will bounce. **P2**
- **"carbon-negative"** (`dictionaries.ts:51`) — Hedera's marketing claim, unverifiable from the code, sits next to two verifiable specs borrowing their credibility. **P2**
- **Locked builders-room copy says "No shortcuts, no buying in."** (`ChatRoomClient.tsx:183`) — while a hardcoded founder bypass exists (`lib/server/badges.ts:68`). Legitimate, but the absolutist copy is a lie-in-waiting. **P2**
- **Dead copy never rendered:** `landing.track*` transparency section and `landing.feeS*` steps exist in `dictionaries.ts:79-106` but are never referenced by `app/page.tsx`. Harmless (i18n parity tests pass), but unmaintained. **P2**
- **Referral copy "earns referral credit"** — credit = a count + tiered badges, no HBAR, no fee share. User copy is accurate today; don't let marketing drift toward implying monetary rewards. **P2**
- **"Earns referral credit" link shapes:** `ShareButtons` → `/username?ref=x`; `ReferralCard` → `/?ref=x`. Both captured, no breakage — two sources of truth. **P2**

### "Living town" gaps
- **ActivityTicker renders nothing until first load and stays hidden when empty** (`components/ActivityTicker.tsx:42`) — the "● live" strip is invisible exactly when the town is quiet, when it's needed most. Should say "Quiet right now — start something." **P2**
- **PresenceDot renders nothing when count is 0** (`components/Presence.tsx:61-62`) — "0 here" is more honest than absence. **P2**
- **Notification bell is tips-only and decorative for the social layer** (`components/NotificationBell.tsx`) — no DM, reply, or mention notifications; **no mention system exists at all** in the codebase. A user gets no signal that someone replied to them. **P2**
- **TrendingFeed vanishes when empty or failed** (`TrendingFeed.tsx:28-30` returns `null`) — the 🔥 heading disappears; a broken API is indistinguishable from "no data". Rows aren't links (dead-end UI). No pagination (hard top-10). **P2**
- **Splash screen** (`components/Splash.tsx:96-108`) — full-viewport entry gate with no skip affordance, and an 804 KB PNG (`public/voicescape-banner.png`) with `priority` on mobile data. Consider the 102 KB JPG or WebP, plus a subtle skip link. **P2**

### Mobile layout (360px)
- **WalletConnect authenticated row can overflow** (`WalletConnect.tsx:115`) — `display:flex` with **no `flex-wrap`**: bell + "My Page" + address chip + "Sign out" ≈ 370px in ~324px of content. (The not-connected branch has `flexWrap: "wrap"`.) **P2**
- **Sticky town-hall nav wraps to 2–3 rows** (`.th-nav`, `townhall.css:25-30`) — usable, no overflow, but can consume ~1/4 of a 360px viewport. Consider a horizontally scrollable single row. **P2**
- **Chat scroll hijack** (`ChatRoomClient.tsx:104-106`) — `scrollIntoView` on *every* new message, including while reading history; feed is unbounded (no max-height), so the composer sinks on busy rooms. Sticky composer or "new messages ↓" pill. **P2**
- **DM recipient input** — placeholder says "Recipient address (0x…)", but a HashPack user pasting `0.0.x` gets "Invalid recipient address" with no format hint. **P2**
- **DM background tabs go stale** — `setInterval(...,10000)` throttles on backgrounded Android tabs, no `visibilitychange` refetch (Presence has one; DMs doesn't). `loadThread` also lacks try/catch. **P2**
- **Polls vote has no mirror-lag retry** (`PollsClient.tsx:68-101`) — chat retries 3×, polls don't; spurious "Request failed" after a successful on-chain vote. **P2**
- **Dead UI:** `✕ connection failed` text (`ChatRoomClient.tsx:226`) is unreachable (the null-URL case renders the locked view instead); `useStream` has no terminal failure state — "reconnecting" never resolves to an error. **P2**
- **Session expiry** — no "Session expires in N days" hint (`WalletConnect.tsx:190`); the forced re-sign arrives unexplained. **P2**
- **Publish confirm loop vs screen lock** (`app/builder/page.tsx:1660`) — 30s of polling; if the phone sleeps mid-confirm, the page can sit at "Confirming on-chain…" forever with no retry button. Low-probability, high-confusion. **P2**
- **Purchase history is localStorage-only** (`lib/townhall.ts:314`) — vanishes on device change/wipe with no indication it isn't authoritative; the on-chain `PurchaseCompleted` event is the real record. **P2**

### SEO / robustness
- **Sitemap omits `/agents` and `/explore`** (`app/sitemap.ts`) — both exist, weaker discovery. **P2**
- **Explore hardcodes `voicescape.vercel.app`** (`app/explore/page.tsx:155-157`) while canonical origin is env-driven (`lib/seo.ts:siteUrl()`). Wrong domain in the share box if it ever changes. **P2**

1. **P0-1** — Tips env fallback to the hardcoded mainnet address + human error copy

4. **P1-2** — `verifyTipOnChain` handles EVM tx hashes / honest "submitted" state for MetaMask
5. **P1-4** — Forum/CommentWall: visible errors + retry on verify failure (user paid a fee)
6. **P1-3** — Badge cache invalidation on tip receipt (or recheck button + "couldn't verify" state)
7. **P1-7** — Referral HCS submit gets its own status line (never pop an unexplained prompt on "Published!")
8. **P1-8/P1-9** — Landing cost disclosures (HBAR gas, AI-edit pricing, tip cost in cents not $0.0001)

10. **P1-12** — Humanize all env/config errors at the UI boundary (one shared helper)
11. **P1-5/P1-14/P1-13/P1-10/P1-11** — next pass
